## 1. Context & Problem Statement

AI agent environments (e.g., Claude Desktop, Antigravity, Cursor) use the Model Context Protocol (MCP) to interact with external tools and services. By convention, agent clients launch MCP servers as external child processes communicating over standard input/output (`stdio`) using JSON-RPC 2.0.

Evolus Pencil is a desktop GUI application built on Electron. We need an architecture that allows external AI agents to access Pencil's rendering engine, stencil catalogs, and canvas state with minimum latency and high reliability, without interfering with the desktop user experience or corrupting stdio communication channels.

---

## 2. Decision Drivers

1. **Protocol Compliance:** Must cleanly implement official `@modelcontextprotocol/sdk` and support standard `stdio` and optional `SSE` transports.
2. **Desktop Interactivity:** The user should be able to view designs generated by an agent live in their open Pencil application window.
3. **Stdio Channel Hygiene:** Electron applications often write native logs, Chromium output, and debug messages to `stdout`/`stderr`, which would corrupt JSON-RPC 2.0 frames over `stdio`.
4. **Performance & Reliability:** Near-instantaneous response times for rendering and catalog lookups.

---

## 3. Considered Options

### Option A: Embedded MCP Server Inside Electron
Embed the MCP server directly into Electron's main process and launch Electron whenever the agent triggers an MCP tool.
- *Downsides:*
  - Slow cold boot time for each agent session.
  - Chromium/Electron output easily pollutes standard output, breaking JSON-RPC stdio parsers.
  - Inability to attach to an already running desktop instance without complex IPC multiplexing.

### Option B: Decoupled Standalone Node.js CLI + Internal HTTP Bridge (Chosen)
1. **Internal Bridge (`app/tools/api-server.js`):** Pencil already runs an internal Express HTTP server on `http://127.0.0.1:1919`, loaded directly into `app.xhtml` with full access to `ApplicationPane._instance`.
2. **Standalone MCP Server CLI:** A dedicated Node.js CLI script using `@modelcontextprotocol/sdk`. The agent launches this script via `stdio`. The MCP server forwards requests to `http://127.0.0.1:1919`.

---

## 4. Decision & Rationale

We choose **Option B (Decoupled Standalone CLI + Internal HTTP Bridge)**:
- **Purity of stdio:** The Node.js CLI guarantees 100% clean stdio streams for JSON-RPC 2.0 without Chromium debug interference.
- **Instant Response:** Because Pencil is already running as a desktop app, requests to `http://127.0.0.1:1919` are processed in memory with near-zero latency.
- **Live Collaboration:** When an agent invokes tools with `openAsDocument: true`, the user sees the canvas update immediately inside their active Pencil desktop window.
- **Graceful Diagnostics:** If Pencil is closed, the CLI reports an explicit `PENCIL_NOT_RUNNING` error instructing the user to launch Pencil.

---

## 5. Consequences & Guidance

1. **API Server Expansion:** As new tools are added (e.g. `pencil_list_collections`, `pencil_get_active_document`), corresponding endpoints must be added to `app/tools/api-server.js` interfacing with `ApplicationPane`.
2. **Port Configuration:** Port 1919 is configured in `.project-info/local.env`. Both the API bridge and MCP CLI will consume this configuration.
3. **Task Progression:**
